# be-DailyJob 

> 이 회고는 작업량을 보고하기 위한 문서가 아니라, 
> 오늘 내가 어떤 판단을 했고 어떤 개발 행동을 반복하거나 바꿔야 하는지 확인하기 위한 기록입니다. 
> 각 항목은 길게 쓰기보다, 사실/판단/근거/다음 행동이 드러나게 구체적으로 작성하세요.

### 1. 오늘 완료한 것
- 오늘 실제로 끝낸 기능/수정/학습:
  - 알림 저장 소실 복구 배치 구현
    - notification에 type 필드 추가: AUCTION_OPENED, OUTBID, AUCTION_WON, AUCTION_UNSOLD
    - bids에 notification batch용 인덱스 추가
    - Auction, Bid Repository에 batch용 쿼리 추가
- (오늘의 목표 중에서) 아직 끝내지 못한 부분:
  - 리팩토링: 경매 생성 알림을 찜목록 불러와서 유저당 하나씩 저장하지 않고 batch insert

### 2. 오늘 가장 의미있었던 기술적 판단
- 내가 내린 판단: 인덱스를 최소화 했다. bid 스키마에 status index만 추가.
- 그렇게 판단한 이유: 배치 처리를 위해 입찰과 경매 스키마에 인덱스를 넣을까 했는데, 배치 처리를 효율적으로 하려고 인덱스를 넣는게 프로젝트 핵심 로직의 쓰기에 영향을 미치는 게 적절하지 않다고 생각했다. 
- 고려했지만 선택하지 않은 대안: bid 스키마와 auction 스키마에 복합 인덱스를 마구마구 추가하기
- 이 판단이 코드 품질/테스트/유지보수에 미친 영향: 배치가 너무 느려진다 싶으면 필요할 때 넣는 것으로 했다. 핵심 로직의 응답속도 지연을 최소화 하는 원칙을 지켰다.

### 3. 가장 막혔던 문제와 해결 과정
- 문제 상황 또는 증상: S3 연결을 로컬에서 하고 싶은데, edu 계정에 정책 추가 권한이 없어서 할 수 없었다.
- 원인을 확인하기 위해 시도한 방법: 정책을 받기 위해 권한을 요청하려고 했다.
- 실제 원인: edu 계정에 S3 Full Access 권한이 있어서 정책 설정을 할 필요가 없었다.
- 해결 방법: 로컬 터미널에서 aws 명령어로 액세스 키와 시크릿 토큰을 저장하고, mfa 자격증명을 추가하면 된다.
- 다음에 비슷한 문제가 생기면 먼저 확인할 것: 우선 잘 아는 분께 질문을 하자.

### 5. 오늘 아쉬웠던 행동(개발과 관련된 것)
- 비효율적이었던 접근/놓치거나 부족했던 점: 팀원 분들이 테스트 시나리오 짜고, 테스트 스크립트 짜고 서버에 연결하고 하는데 그 흐름을 따라가지 못했다.
- 그렇게 된 원인: 테스트 쪽은 아예 모르기도 하고, 테스트의 중요성을 잘 모르는 것 같다. 또 테스트 수행할 때 변인 통제가 잘 안되고 모니터링도 뭐 해야할 지 모르니까 원인 파악이 어려운 것 같다.
- 다음에는 다르게 해볼 구체적인 행동: 테스트 스크립트에 대해서 좀 찾아보고 와야겠다.
